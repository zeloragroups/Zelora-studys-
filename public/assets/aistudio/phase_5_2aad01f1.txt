- Their assigned classes.
- Their assigned batches.
- Their assigned subjects.
- Relevant scheduled sessions.

Provide a clear workflow:

1. Select an assigned class.
2. Select an assigned batch.
3. Select the attendance date.
4. Select the relevant subject or scheduled session.
5. Load enrolled students.
6. Mark attendance.
7. Review the complete attendance list.
8. Submit attendance.
9. Show a successful submission confirmation.

The teacher must not see students from unrelated batches.

Use the existing TeacherAssignment, StudentEnrolment and TimetableEntry relationships.

7. ATTENDANCE STATUSES

Support these statuses:

- Present.
- Absent.
- Late.
- Excused.

Use clear visual indicators and labels.

Rules:

- Every enrolled student must have an attendance status for a submitted session.
- Do not silently mark students absent when a teacher forgets to mark them.
- Incomplete attendance must be clearly identified.
- Teachers must be able to review all statuses before submission.
- Prevent accidental duplicate submissions.

Define the attendance calculation rules clearly.

For the default attendance percentage:

- Present counts as attended.
- Late counts as attended.
- Absent does not count as attended.
- Excused is excluded from the percentage denominator.

Display the numerator and denominator where useful so the percentage is understandable.

8. DAILY ATTENDANCE

Support attendance for regular scheduled classes.

Use:

- Existing active student enrolments.
- Existing teacher assignments.
- Existing timetable records.

Validate:

- Teacher is active.
- Student account is active.
- Enrolment is active.
- Teacher has the relevant active assignment.
- Selected batch belongs to the selected class.
- Selected subject is valid.
- Selected date is valid.

Do not allow teachers to mark attendance for classes or batches they are not assigned to.

Prevent duplicate attendance records for the same student and session.

If a timetable session is cancelled, do not allow attendance to be submitted for that cancelled session.

9. EXAM-DAY ATTENDANCE

- Enter an exam title or reference.
- Select the date.

12. IN-APP ABSENCE NOTIFICATIONS

When submitted attendance contains an Absent student, create an in-app absence notification.

The notification must contain:

- Student name.
- Student ID.
- Absence date.
- Class.
- Batch.
- Subject.
- Attendance type: regular or examination.
- Notification creation time.
- Read/unread status.

Target the notification to:

- The affected Student account.
- The Admin account or Admin notification centre.

Parents will use the Student account, so they can see the same notification.

Do not create a separate Parent account.

Notification requirements:

- Create notifications only after successful attendance submission.
- Do not create notifications for draft attendance.
- Do not create absence notifications for Present, Late or Excused statuses.
- Prevent duplicate notifications for the same absence event.
- If an absence is corrected, update the notification state or create an appropriate correction notice so users are not misled.
- Show notifications in the existing dashboards.
- Support marking notifications as read.
- Display unread notification counts.
- Keep notification history.

Do not send WhatsApp messages, SMS or emails.

Do not claim any external notification was delivered.

15. ATTENDANCE PERCENTAGE CALCULATIONS

Use one consistent calculation method across Admin, Teacher and Student views.

Formula:

Attendance percentage = (Present + Late) / (Present + Absent + Late) × 100

Excused sessions are excluded from the denominator.

If the denominator is zero:

- Display "Not available" or an equivalent clear empty state.
- Do not divide by zero.
- Do not display an invented percentage.

Keep calculations in a shared utility or service rather than duplicating formulas across components.

Document the formula.
