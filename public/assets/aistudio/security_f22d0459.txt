2. AUTHENTICATION SECURITY

There are exactly three application roles.

Admin

Admin authentication must use Google Sign-In only.

The only authorized Admin Gmail is:

"07alphabro@gmail.com"

Requirements:

- Only this authorized account can access Admin.
- Other Google accounts must be denied.
- Do not allow public Admin registration.
- Do not trust frontend email checks as the sole authorization mechanism.
- Verify the authenticated Google identity through Firebase Authentication.
- Enforce Admin authorization through trusted authorization checks and Firestore Security Rules.
- Verify the Admin account is active.
- Do not permit unauthorized users to create their own Admin privileges.
- Prevent unauthorized modification of Admin allowlists.
- Protect changes to the Authorized Admin Gmail setting.
- Require secure reauthentication and a trusted authorization process before changing the authorized Gmail.

Check whether Admin authorization is based on a stable Firebase UID, rather than relying only on an editable email field.

If the existing implementation uses an unsafe bootstrap process, report and correct it without locking out the legitimate Admin.

Teacher

Teacher authentication must remain:

- Teacher ID + Password.
- No Google Sign-In.
- No public registration.
- No access to Admin pages.
- No ability to create Admin accounts.

Student

Student authentication must remain:

- Student ID + Password.
- No Google Sign-In.
- No public registration.
- No access to Admin pages.
- No ability to access another Student's private information.

Session security

Audit:

- Firebase authentication state.
- Token validation.
- Session expiration.
- Deactivated accounts.
- Revoked access.
- Logout behaviour.
- Authentication race conditions.
- Role changes during active sessions.
- Direct route access without authorization.

Do not rely on hiding navigation links to protect routes.

Every protected operation must enforce authorization independently.

3. FIREBASE FIRESTORE SECURITY RULES

Perform a complete review of "firestore.rules".

Use deny-by-default rules.

Check every collection and nested document.

Verify:

- Authentication is required for protected data.
- Admin-only collections are Admin-only.
- Teacher queries are restricted to assigned classes and permitted records.
- Students can access only their own records.
- Students cannot modify fee balances.
- Students cannot verify payments.
- Teachers cannot modify Admin settings.
- Teachers cannot access other Teachers' private records.
- Teachers cannot access unrelated Students.
- Students cannot access examination answer keys.
- Students cannot access private teacher notes.
- Unreleased marks remain private.
- Payment verification remains Admin-only.
- Audit records cannot be modified or deleted by unauthorized users.
- Account mappings cannot be modified by clients.
- Role and ownership fields cannot be changed by unauthorized users.

Review all operations separately:

- get
- list
- create
- update
- delete

Do not assume that a secure "get" rule automatically makes a "list" query secure.

Firestore queries must satisfy the security rules for every possible returned document.

Review array-based ownership checks carefully, including "teacherUids" and "studentUid".

Do not weaken authorization merely to make a query work.

Check for:

- Missing field validation.
- Unexpected fields.
- Type confusion.
- Invalid UID values.
- Unauthorized ownership changes.
- Privilege escalation.
- Unrestricted collection queries.
- Unsafe wildcard matches.
- Rules that accidentally grant broad access.

Preserve legitimate application workflows while correcting vulnerabilities.

4. FIREBASE STORAGE SECURITY

Review "storage.rules".

Verify:

7. DATA PRIVACY AND ROLE ISOLATION

Student and Teacher information is sensitive.

Review the following data:

- Student names.
- Student IDs.
- Attendance.
- Academic performance.
- Examination marks.
- Homework submissions.
- Fees.
- Payment claims.
- Receipts.
- Teacher assignments.

- Notifications.
- Query listeners.
- Shared application settings.
- Error messages.
